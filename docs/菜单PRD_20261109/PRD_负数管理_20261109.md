## §2 背景与目标

- 目标：以新增和操作记录维护负数资格，禁止编辑覆盖历史。
- 使用者：账房操作人员、业务复核人员及获授权的管理人员。
- 范围：本菜单页面及关联弹窗；公共检索、时间控件、币种规范引用公共文档。
- 当前原型边界：仅管理原型中的负数资格，不表示所有交易已联动透支权限。

## §3 功能清单

| 页面 | 页面名称 | 变更类别 | 业务结果 |
|---|---|---|---|
| P1 | 负数资格列表 | [MOD] | 展示新增及移除操作，当前有效资格可移除；操作栏提供操作记录，不提供编辑。 |
| P2 | 新增、移除与记录 | [MOD] | 所有操作新增记录，不覆盖旧记录；历史按户口归集。 |

## §4 功能细节规格

### 4.1 P1 负数资格列表

- 界面：统一账房视觉、户口检索与时间筛选；列表不显示确认人。
- 页面逻辑：展示新增及移除操作，当前有效资格可移除；操作栏提供操作记录，不提供编辑。
- 业务处理：查询、预览不产生资金变动；只有合法提交才能产生业务记录。取消关闭不得记成功；此规则为正式交付要求，原型覆盖范围以 §2 为准。
- 正向流程：操作人进入页面，完成有效查询或填写，核对结果后执行对应操作，看到列表或记录更新。
- 异常流程：同户口已有有效资格时禁止重复新增。
- 边界：移除后允许按规则重新新增，原记录保留。
- 联动范围：只更新对应户口、币种及关联业务；本轮未授权跨菜单数据变更不自动扩大。

### 4.2 P2 新增、移除与记录

- 界面：新增表单选择户口、填写备注；历史弹窗展示操作类型、操作人、时间、备注。
- 页面逻辑：所有操作新增记录，不覆盖旧记录；历史按户口归集。
- 业务处理：查询、预览不产生资金变动；只有合法提交才能产生业务记录。取消关闭不得记成功；此规则为正式交付要求，原型覆盖范围以 §2 为准。
- 正向流程：操作人进入页面，完成有效查询或填写，核对结果后执行对应操作，看到列表或记录更新。
- 异常流程：无效户口或重复提交不能改变状态。
- 边界：没有记录显示空态，初始演示资格可查看其初始新增记录。
- 联动范围：只更新对应户口、币种及关联业务；本轮未授权跨菜单数据变更不自动扩大。

## §7 页面设计

### 7.1 P1 负数资格列表

- 布局：统一账房视觉、户口检索与时间筛选；列表不显示确认人。
- 表现：采用账房管理的白底卡片、青色主操作、统一表单高度；金额与表头对齐。
- 反馈：区分未填写、无结果、校验失败、成功；不得用零值替代加载失败。

### 7.2 P2 新增、移除与记录

- 布局：新增表单选择户口、填写备注；历史弹窗展示操作类型、操作人、时间、备注。
- 表现：采用账房管理的白底卡片、青色主操作、统一表单高度；金额与表头对齐。
- 反馈：区分未填写、无结果、校验失败、成功；不得用零值替代加载失败。

## §9 验收清单

### 9.1 功能验收

| 编号 | 页面 | 验收标准 | 状态 |
|---|---|---|---|
| AC-01 | P1 | 列表无编辑按钮和确认人列；重复新增不产生第二条有效资格。 | 待验收 |
| AC-02 | P2 | 新增和移除后均可查看记录；历史保留全部事件。 | 待验收 |

### 9.2 非功能验收

- 详见配套附录 A4；金额、户口和操作历史必须可辨识，控件不互相遮挡。
- 带权限的正式操作必须验证执行人身份；演示密码非空检查不能作为生产权限验收。

### 9.3 异常验收

- 对 §8 每个案例验证：失败不产生新资金记录，已有业务状态不被部分修改。
- 取消、重复点击、返回后重新打开的结果与既有成功记录一致；需持久化的正式业务重载后不丢失。

### 9.4 本菜单专项验收

- 按 §2 原型边界区分“原型交互可用”与“生产账务已验收”，不得混签。
- 逐项解决附录 A9，再执行正式账务、权限和异常测试；所有适用验收项通过后才能签收。
