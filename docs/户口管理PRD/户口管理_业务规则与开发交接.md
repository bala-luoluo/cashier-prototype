# 户口管理：业务规则与开发交接

日期：2026-10-31。配套 [[PRD_户口管理调整_20261031]] 与 [[PRD_户口管理调整_20261031_appendix]]。

本文件集中列字段建议、计算示例及测试数据。明确业务要求与待确认技术口径分开，不代表已完成接口或数据库设计。

## 1. 金额精度规则

### 1.1 已明确

- 输入金额和计算结果精度为四位小数，超出部分直接舍去，不四舍五入。
- UI显示、存储结果、流水、报表和导出必须一致；不能仅用显示格式掩盖真实高精度金额。
- 四位精度的计量单位未确定。当前页面多处写“万”，不能直接默认按元保存四位再按万展示四位。

### 1.2 建议实现约定（Q1确认后才可作为计算合同）

- 使用十进制定点计算；按确定的业务单位定义截断函数 T4。
- T4(x) = trunc(x × 10000) / 10000，trunc向零取整。
- 金额输入超过四位时，在失焦或确认前展示截断后的实际提交金额，提示“超过四位部分已舍去”。不能无提示地提交不同金额。
- 汇率不是输入金额，其允许精度独立确认；不要擅自将汇率也截断四位。
- 建议中间计算保持足够精度，只对最终入账值做T4；是否每一步截断必须由业务确认。
- 零显示为0.0000，负零归零；空值与加载失败不能显示成0.0000。
- 转账、冻结、解冻、换汇金额要求大于零；资金方向由操作类型决定，不让用户用负数反向执行。

| 示例 | 建议T4结果 | 用途 |
|---|---:|---|
| 1.23459 | 1.2345 | 证明不是四舍五入 |
| 1.99999 | 1.9999 | 跨整数边界不进位 |
| 0.00009 | 0.0000 | 截断后为零的交易应拦截 |
| -1.23459 | -1.2345 | 负数采用向零截断为建议，待确认 |
| 1 基础货币单位换为万 | 0.0001万 | 1万=10000基础单位 |
| 0.0001万 | 1基础单位 | 解释单位影响，而不是确定系统精度 |

## 2. 现金与冻结变化

定义：C为显示现金余额，F为剩余冻结金额，a为本次操作金额。按同户口、同币种、同单位处理。

### 2.1 已确认的冻结口径

- 冻结：C' = C − a；F' = F + a。
- 指定币种全额解冻：a = 当前该币种F；C' = C + F；F' = 0。不选择原冻结单，不输入部分解冻金额。
- 不得在换汇/转账等校验时再用C − F，否则会重复冻结。
- 纯冻结/解冻前后 C + F 应保持不变。该值用于核对，不要求新增“现金总余额”界面列。

| 顺序 | 动作 | C显示现金 | F冻结金额 | 核对值C+F |
|---|---|---:|---:|---:|
| 0 | 初始 | 100.0000 | 0.0000 | 100.0000 |
| 1 | 冻结20 | 80.0000 | 20.0000 | 100.0000 |
| 2 | 解冻指定币种（全部金额20） | 100.0000 | 0.0000 | 100.0000 |

### 2.2 其他操作建议基线

| 操作 | 对当前户口现金影响 | 关联 |
|---|---|---|
| 存款a | C增加a | 存款流水、报表 |
| 取款a | C减少a | 取款流水、报表 |
| 同币种转出a | 付款方C减少a；收款方C增加a | 同一业务号串联两端 |
| 换汇 | 来源币种C减少转出额；目标币种C增加换算结果 | 币种对、运算方式和汇率固定入记录 |
| 收工存卡 | 不直接增加C | 存卡S及场次关联 |
| 上下数交收完成 | 仅满足转现金前置条件 | 实际转换触发、金额、手续费等未定 |

负余额业务范围需和已有负数管理规则统一。未确认前不默许透支，也不能声称所有现有负数行为都要禁止。

## 3. 换汇计算合同与算例

### 3.1 规则

- 输入A（转出金额）、r（汇率）、源币种、目标币种及对手户口。
- 系统算法为乘法时 B = T4(A × r)，为除法时 B = T4(A ÷ r)，均要求 r>0；业务页面无算法选择。
- A使用已确认截断后的金额；币种不同；A>0且B>0；预览与实际入账完全一致。
- 显示“1源币种对应多少目标币种”或等价清楚说明，并保留乘法完整过程，避免仅显示裸汇率。
- 换汇样例汇率均为测试常数，不是实时汇率或业务报价。

| 测试 | 输入 | 精确计算 | 入账结果 |
|---|---|---|---:|
| FX-01乘法 | A=100.1234，r=0.92345 | 92.45895373 | 92.4589 |
| FX-02默认乘法 | A=100.0000，r=7.8 | 780 | 780.0000 |
| FX-03非法汇率 | r=0 | 不计算 | 禁止提交 |
| FX-04极小结果 | A=0.0001，r=0.1，乘法 | 0.00001 | 0.0000，禁止提交 |
| FX-05余额变化 | 预览时足额，提交前另一交易扣款 | 按最新余额复核 | 不足则失败，不产生单边记账 |

### 3.2 原子性与结果未知

- 同一笔换汇扣款、入款、流水同时生效或全部不生效。
- 网络超时不是业务失败。用原操作标识查询结果，不重新创建另一笔。
- 预览不产生资金流水；提交后记录实际输入、运算方式、汇率、截断结果、操作人和时间。

## 5. 个人码粮规则：明确项与禁止猜测项

明确：按客户、币种配置，仅设置占成比对应码粮比，分即结和月结。A数码粮、现金码粮、M码粮、积分比、代理佣差均从本次个人设置移除。

待业务给出：

1. 每一种角色对应的适用佣金模式。
2. 占成比例与码粮比是一档还是多档、基数及应用顺序。
3. 已移除比例项的旧配置如何停用及迁移，历史记录如何保留。
4. 原“月结码粮”旧值如何映射到月结的对应码粮比，不直接覆盖历史。
5. 每币种同时保存即结、月结两套比例；开工按所选结算方式引用，历史场次保持已保存的当场快照。
6. 个人与默认继承是整套还是逐字段；新设置在进行中/未结算场次是否生效。
7. 月结截止时区、跨月、冲正及比例范围。

样例模板：角色→币种→周期→本金来源→转码基数→占成档→适用比例→佣金结果→是否影响现金。业务至少提供每类规则一个正常和一个边界样例后再实现计算。

## 6. 备注与授权约束

- 备注可见条件建议为：有户口访问权限，并且为所有有权人员可见或当前人位于指定名单。
- 编辑/删除/查看历史需独立权限；备注编辑权限不能自动覆盖阅读范围。
- 列表、搜索、导出和日志的正文都要执行相同规则，不能只在前端隐藏。
- 授权人弹窗隐藏确认人选择框及操作人只读信息，保留操作人密码、确认人密码；正式双人鉴权机制继续保留，确认人身份来源需核对。
- 当前组别/编号直接编辑保存并校验重号；历史审批方案暂不启用，正式流程待确认。

## 冻结列表的数据联动补充

- 原型已实现当前会话内跨新开户的流水留存、资料修改映射、页签筛选及CSV汇出。浏览器刷新恢复演示数据，不代表服务端持久化完成。

## 存取款报表实现交接

- 资金操作、余额更新和资金流水正式必须同事务落库，操作ID保证幂等。流水记录余额类别（现金/存卡）、账户稳定ID、户口资料快照、金额符号、币种、交易后余额、收款账户、备注和关联场次。
- 报表资金流水独立于当前户口详情数据保存；开户不能清空全局报表。冻结流水不进入资金收支报表。
- 原型已连接且本报表仅接收存款、取款、转账、存卡开工、收工存卡、加彩存卡六类操作；其他账户及真实交收的后台联动仍待实现。原型刷新后恢复，不提供服务端持久化。
- Excel按钮当前输出Excel可读的HTML表格格式 .xls，生产应替换为标准 .xlsx，避免客户端格式提示；正式导出处理公式注入、授权及大数据量。

## 系统汇率与双账户换汇（2026-11-03）

- 算法为乘法时 B＝truncate4(A × r)，除法时 B＝truncate4(A ÷ r)；r与算法均来自系统设置的“原币种→目标币种”，不接收业务客户端自定义算法或汇率。金额使用定点数，汇率保留配置精度。
- 本账户原币种余额−A，目标币种余额+B；对手原币种余额+A，目标币种余额−B。分别生成四条带正负金额的流水，保存各条入账后余额；共享exchange业务单号。
- 余额变更、换汇单、四条资金流水应在同一事务内提交，业务请求唯一键去重；并发扣款需要锁定或等价版本校验。任一失败整笔回滚。
- 存款/取款成功各新增一条存取款记录；转账生成双方收付记录；冻结/解冻进入冻结报表，整户状态冻结不伪造金额流水；开工按实际存卡、换汇及M资金来源进入对应报表。
- 原型已覆盖普通户口换汇的双方余额及四流水；交易数据仅在当前会话内保存。换汇开工/加彩的对手端记账仍需按场次资金来源进一步联调，不等同已完成四流水验收。
