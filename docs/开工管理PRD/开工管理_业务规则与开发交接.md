# 开工管理 · 业务规则与开发交接

日期：2026-10-31。配套《开工管理调整PRD》。本文件区分截图明确、用户确认、现有界面沿用与原型建议；原型不连接真实交易或消息服务。

## 1 统一单位与术语
| 符号 | 含义 | 口径 |
| --- | --- | --- |
| C / S / M | 开工现金 / 提存卡 / M资金 | 资金来源，可组合，同币种 |
| P | 初始开工本金 | C + S + M，不包含后续加彩 |
| A | 加彩累计本金 | 各次追加资金之和，不能再并入P重复减 |
| R | 当前累计转码 | 开工泥码与后续变动形成的累计 |
| N / X | 本次泥码 / 现金码 | 均为非负输入，单位万 |
| Dn / Dx | 中途存泥码 / 现金码净余额 | 各类累计存入减各类累计取出 |
| K | 场中K现总额 | 泥码与现金码两者合计 |
| T | 暂存累计扣减上下数金额 | 各次暂存泥码与现金码合计 |
| L / E | 收工离台泥码 / 现金码 | 用于计算实际转码与盈亏 |
| Y | 上下数 | 正数＝客人赢，负数＝客人输；公司视角相反 |
| Rs | 本场实际转码 | 当前累计转码减收工离台泥码 |
| p / r | 占成比 / 代理支付码粮比 | 百分比输入，例如40代表40%，0.08代表0.08% |

- 界面金额单位为万，四位小数；这意味着0.0001万为1基础货币单位。若某币种需要更小最小单位，需另行确认输入/显示粒度，不得暗中提高或舍弃精度。
- 正负计算结果向零截断到四位小数，例如1.23459→1.2345，-1.23459→-1.2345。
- 原型用四位定点整数和整数乘除；百分比计算最后截断。不以浮点数乘后四舍五入。
- 密码只用于当前提交校验，原型不会保存密码；正式身份确认由服务端完成。

## 3 收工建议公式与待确认边界
- 实查现网：实际转码＝累计转码－离台泥码；上下数包含离台筹码、中途净存、场中K现，减本金。
- 收工采用：Y = L + E + Dn + Dx + K − T − P − A + Tips。Tips 为本场员工和荷官现金码小费合计。
- 该总公式为结合现网和新需求的建议，尚未经过业务对账签收（Q-06）。暂存取回、未收回筹码、M还款和跨币种情况不能擅自代入。
- 收工分配采用本文件“收工金额分配公式”；先还本场未还M，再分配存卡、存现及K现金。
- 收工K现仅处理本次输入，不再次把历史场中K现计入公司现金扣减。
- 存入户口只增加对应币种存卡，不直接加现金；交收后何时转现金沿用户口管理规则。
- 普通客户佣金和隐藏占成/占成码粮是独立业务。移除“结算本场佣金”勾选，保留预计金额展示，不执行佣金付款，实际入账规则仍待确认。普通佣金展示仅用演示费率，正式以户口方案及结算周期为准。

## 4 占成与码粮的两笔转账
| 客人结果 | 占成款 | 码粮款 | 隐藏占成的户口 | B数的户口 |
| --- | --- | --- | --- | --- |
| Y>0 客赢 | abs(Y)×p÷100 | Rs×r÷100 | 隐藏占成户口→公司户口 | 开工户口→公司户口 |
| Y<0 客输 | abs(Y)×p÷100 | Rs×r÷100 | 公司户口→隐藏占成户口 | 公司户口→开工户口 |
| Y=0 平局 | 占成金额为0 | 方向未定义 | 阻止默认结算 | 阻止默认结算 |

- 两笔独立展示、独立留痕，可关联同一场次/结算批次，但不只展示净额。零金额不生成资金流水。
- 公司户口来自中转户大账户配置；原型标签为COMPANY_STOCK，不代表真实线上配置已读到。
- 方案在开工时快照保存，后续配置修改不追溯改变本场。B数不另建占成人户口。
- 多隐藏占成时逐户计算；占成比例总额限制、重复户口和层级冲突应由业务确认。原型不允许同场重复隐藏占成户口。
- 原型没有实际转账余额账本；正式需核验币种、转出可用余额、收款状态和原子性。

## 6 操作记录与消息
- 操作信息至少含场次号、操作类型、币种、金额组成及结果；不得以备注作为唯一的金额来源。
- 消息触发类型限定加彩、中途存、中途取、K现、暂存、小费。原型在成功时建立一条待发送记录，可预览；不发送到外部。
- 建议客户消息：类型＋场次号＋户口号＋币种＋泥码/现金码或资金来源金额；禁止附带密码、内部备注、系统权限信息。
- 真实渠道失败仅重试消息，不能重做资金操作。发送幂等关联业务操作ID；缺收件号码时有可追溯失败原因。

## 2026-11-01 原型增量交接

- 当场比例保存独立快照，个人即结/月结两套配置同时存在；0为有效值，空值才回退默认。
- 开工本金＝现金＋M＋普通存卡＋换入目标金额；换入金额按系统汇率系统配置的乘法或除法计算，保留四位小数、超出截断。汇率最多六位小数。

- 银头变化、换汇正式账户范围、即时取价与逆向冲正仍待确认，不能将原型演示值作为生产规则。
- 通知保存业务类型、时间、操作人及字段快照；摘要、完整预览、复制使用同一快照。仅在业务成功后生成，未发送不标记送达。
- 个人数据修改不改历史通知；未知数据显示—。欠款来源尚待对接正式数据，不从M欠款推算现金/积分垫付。

## 2026-11-02 计算与验收补充

- 收工上下数 = 离台泥码 + 现金码 + 中途存余额 + K现 − 暂存 − 开工本金 − 加彩 + 本场小费合计。
- 中途存余额 = 累计中途存泥码及现金码 − 累计中途取泥码及现金码；改显示名称不改此口径。
- 小费合计 = 本场员工与荷官的泥码、现金码小费；只在最终收工公式加入一次，不改变收工筹码合计；员工泥码在给出小费时已扣转码，收工不得再次扣减该笔转码。
- 还M = min(收工筹码合计, 本场未还M合计)。取现 + 存卡 = 收工筹码合计 − 还M。
- 每单本次还款不超过未还额；按本场开工M、加彩M顺序分配，按对应户口、场次币种恢复已偿还的可用M额度。未使用额度不作为未还额。
- 示例：本金10，中途存余额3，K现1，暂存1，加彩2，离台泥码4、现金码3，小费0.5，最终上下数为-1.5；还M不再改变此值。
- 示例：未还M10、收工筹码5，本次还5、仍欠5、取现和存卡均0；筹码15则还10、剩余5可分配。
- 换汇系统配置的乘法或除法，金额四位小数截断、汇率最多六位；对手户口保存到操作快照，开工结果在换汇开工报表展示。
- 现金余额加彩只扣场次币种可用现金；原型与户口模块同步，并生成“取款”流水及业务备注。输入负数、超余额、验证失败不得扣款。
- 正式实现需保证还款、额度恢复、取现/存卡、收工状态及通知快照原子提交和幂等；原型仅为内存演示。
- 原型限制：初始M使用场次关联展示单号，加彩M使用演示单号；真实M单服务、跨场欠款冲抵、手动调整还款顺序及短信备注未接入。不得将截图样例单号当作真实数据。
- 视觉验收：收工保持左右分栏，窄屏自动上下排列；表格不裁切；完整浏览器多尺寸验收尚待执行。

## K现金与员工小费联动验收

- 同币种等额处理：N为泥码、X为现金码；现金减少N+X，公司泥码增加N，公司现金码增加X，当前转码减少N。开工本金及加彩不变。

## 荷官小费与离台数

- 荷官小费T为本次现金码金额，荷官不收泥码：即时上下数增加T、离台数增加T；本金、转码、公司现金/泥码/现金码、户口余额及存卡均不变。
- 收工表单输入的是实际交回筹码，不含已给出的荷官小费；离台数展示与通知使用实际交回泥码+现金码+本场荷官小费累计。
- 收工上下数从原始筹码及历史明细重算，仍按既定公式计入小费一次；不得在含荷官小费的离台数之上再次加同笔荷官小费。
- 已支付的荷官小费不是可再次支付的现金或可用于还M的筹码；分配资金采用实际交回筹码加暂存及中途存净额，详见收工金额分配公式。
- 验收：上下数5、离台数2，给荷官现金码3后为上下数8、离台数5，转码和银头不变；重复提交不再次增加。
- 收工示例：本金20、实际交回泥码10和现金码15、荷官小费3，无其他项；离台数28，上下数8，可用于还M和资金分配的金额25。不能算出上下数11或资金28。

## 收工金额分配公式

- 可分配池 G = 离台泥码 + 现金码 + 暂存 + 中途存累计 − 中途取累计。本原型 depMud+depCash 已是中途存净余额，不再减一次中途取。
- 本次还M H 按未还M与G取较小值，历史已还M不重复扣除。
- 现金来源额度 C0 = 开工现金本金 + 本场现金加彩；现金加彩按资金来源“现金”累计，不混入现金余额加彩、存卡、M或换汇资金。
- 默认存卡 S = max(G − C0 − H, 0)；默认存现 C = min(C0, G − H)。不足时减少存现，存卡最低为0。
- K现金 K 默认为0；现金扣减 min(K,C)，最终存现 = C−min(K,C)，最终存卡 = S−max(K−C,0)。
- 校验 K≥0、K≤C+S；资金不足时自动减少默认存现，不生成负数存卡。
- 最终存现 + 最终存卡 + K + H = G。
- 成功提交：最终存现加到本户同币种余额、最终存卡加到本户同币种存卡；写入存取款报表及场次操作记录，通知分别列出存卡、存现、取现。
- 原型现金加彩从成功记录的现金来源金额累计；存量无结构化现金来源的加彩记录需核对补齐，不能猜测。
